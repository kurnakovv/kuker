## Summary

Introduce a formatting rule for multiline method invocations that enforces consistent placement and alignment of the closing parenthesis (`)`).

The goal is to improve readability by making the boundaries of a method invocation visually explicit and by providing a clear relationship between opening and closing parentheses.

## Scope

This MVP applies **only to method invocations** (`InvocationExpressionSyntax`).

Examples:

```csharp
Foo(
    a,
    b
);
```

```csharp
_db.Items
    .Where(
        x => x.Id == 5
    )
    .ToList();
```

Support for constructors, method declarations, constructor declarations, delegates, etc. is intentionally out of scope for the initial implementation and may be added in future versions.

## Rule Definition

If:

* a method invocation spans multiple lines;
* the opening parenthesis `(` and closing parenthesis `)` are located on different lines;

then the closing parenthesis must:

1. be placed on its own line;
2. be the only non-whitespace character on that line;
3. be aligned with the first non-whitespace character of the line containing the opening parenthesis.

## Terminology

### Opening Line

The source code line containing the invocation's opening parenthesis `(`.

Example:

```csharp
var result = Foo(
```

The opening line is:

```csharp
var result = Foo(
```

### Anchor Position

The column position of the first non-whitespace character on the opening line.

Example:

```csharp
var result = Foo(
```

The anchor character is:

```text
v
```

## Valid Examples

### Single-line invocation

The rule does not apply.

```csharp
Foo(a, b, c);
```

### Multiline invocation

Valid:

```csharp
Foo(
    a,
    b,
    c
);
```

Invalid:

```csharp
Foo(
    a,
    b,
    c);
```

## Fluent/Chained Calls

The anchor position is calculated from the opening line of the specific invocation being analyzed.

Valid:

```csharp
_db.Items
    .Where(
        x => x.Id == 5
    )
    .ToList();
```

In this example, the anchor character is:

```text
.
```

before `Where`.

## Nested Invocations

Each invocation is analyzed independently.

Valid:

```csharp
Foo(
    Bar(
        x,
        y
    ),
    z
);
```

`Bar(...)` uses its own anchor position.

`Foo(...)` uses its own anchor position.

## Exclusions

This rule does **not** apply to:

* method declarations;
* constructor declarations;
* constructor invocations (`new`);
* `base(...)` constructor initializers;
* `this(...)` constructor initializers;
* delegate declarations;
* lambda expressions;
* attributes;
* collection initializers;
* object initializers;
* any syntax node other than `InvocationExpressionSyntax`.

Support for these constructs may be introduced in future iterations.

## Analyzer Logic

For each `InvocationExpressionSyntax`:

1. Obtain the associated `ArgumentListSyntax`.
2. Determine the line containing `(`.
3. Determine the line containing `)`.
4. If both parentheses are on the same line, stop analysis.
5. Find the first non-whitespace character on the opening line.
6. Record its column position.
7. Verify that:

   * `)` is on a separate line;
   * only whitespace exists before `)` on that line;
   * only whitespace exists after `)` on that line.
8. Verify that the column position of `)` matches the anchor position.
9. Report a diagnostic if any check fails.

## Diagnostic

### ID

```text
KUK0006
```

### Title

```text
Incorrect multiline closing parenthesis placement
```

### Message

```text
Closing parenthesis of a multiline construct must be on a separate line and aligned with the first non-whitespace character of the opening line.
```

## MVP Constraints

The initial implementation should support only `InvocationExpressionSyntax`.

Future extensions may include:

* `ObjectCreationExpressionSyntax`
* `ImplicitObjectCreationExpressionSyntax`
* `MethodDeclarationSyntax`
* `ConstructorDeclarationSyntax`
* `DelegateDeclarationSyntax`
* `ConstructorInitializerSyntax`
* other multiline parenthesized constructs using the same alignment model.

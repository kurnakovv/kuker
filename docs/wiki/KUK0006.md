## 💡 Title
Kuk0006MultilineClosingParenthesisAnalyzer

## 🆔 Rule ID
KUK0006

## 📝 Description
This rule detects incorrect placement of the closing parenthesis for multiline method invocations.

For multiline invocations, the closing parenthesis must:
- be on a separate line, and
- be aligned with the first non-whitespace character of the line where the opening parenthesis is located.

## ❔ Why this is a problem
Incorrect parenthesis placement makes multiline calls harder to scan and review. Even small indentation drift in long invocation chains reduces readability and creates unnecessary formatting noise in pull requests.

You can think about it the same way as with `if` blocks: placing the closing `)` at the end of the last argument line is similar to placing the closing `}` of an `if` not on its own final line, but at the end of the last statement inside the block. Technically it may still compile, but visually it weakens structure boundaries and makes code harder to read.

```cs
// ❌ Similar readability issue: closing token is attached to the last code line
if (isValid)
{
    Process();}

Foo(
    1,
    2);

// ✅ Preferred: closing token is on its own final line
if (isValid)
{
    Process();
}

Foo(
    1,
    2
);
```

Also, this pattern appears frequently in AI-generated code: LLMs often keep the closing `)` on the last argument line instead of moving it to a separate aligned line.

This rule enforces one consistent style, so multiline invocations remain easy to read.

## ⚙️ Configuration

You can configure the severity of the rule using .editorconfig.
```.editorconfig
[*.cs]
dotnet_diagnostic.KUK0006.severity = warning # Incorrect multiline closing parenthesis placement | https://github.com/kurnakovv/kuker/wiki/KUK0006
```

## 💻 Examples
```cs
// ❌ KUK0006: closing parenthesis is on the same line as the last argument
var result1 = Foo(
    1,
    2);

// ❌ KUK0006: closing parenthesis is misaligned
var result2 = Foo(
    1,
    2
  );

// ✅ OK: closing parenthesis is on its own line and aligned
var result3 = Foo(
    1,
    2
);
```

Fluent call chain
```cs
// ❌ KUK0006
var result1 = Values()
    .Where(
        x => x > 0)
    .ToArray();

// ✅ OK
var result2 = Values()
    .Where(
        x => x > 0
    )
    .ToArray();
```

## 🗒️ Notes
* Scope | This rule currently analyzes method invocations (`InvocationExpression`) only. In future releases, the same placement rule is planned to be extended to other multiline language constructs as well.

* Single-line invocations | Calls where opening and closing parentheses are on the same line are ignored.

* Nested/compound endings | The analyzer allows closing patterns like `))`, `])`, `})` on one line when the nested closing token is already aligned correctly.

* Code fix | A code fix is available and can automatically align/move the closing parenthesis.

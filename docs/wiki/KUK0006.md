## 💡 Title
Kuk0006MultilineClosingParenthesisAnalyzer

## 🆔 Rule ID
KUK0006

## 📝 Description
This rule detects incorrect placement of the closing parenthesis for multiline argument lists (method invocations, object creations) and parameter lists (method declarations, local functions, constructor declarations, primary constructors).

The exact construct kinds covered by the rule are controlled by `dotnet_diagnostic.KUK0006.syntax_kinds`.

For multiline argument and parameter lists, the closing parenthesis must:
- be on a separate line, and
- be aligned with the first non-whitespace character of the line where the opening parenthesis is located.

## ❔ Why this is a problem
Incorrect parenthesis placement makes multiline calls harder to scan and review. Even small indentation drift in long invocation chains reduces readability and creates unnecessary formatting noise in pull requests.

You can think about it the same way as with `if` blocks: placing the closing `)` at the end of the last argument line is similar to placing the closing `}` of an `if` not on its own final line, but at the end of the last statement inside the block. Technically it may still compile, but visually it weakens structure boundaries and makes code harder to read.

```cs
// ❌ Similar readability issue: closing token is attached to the last code line
if (isValid)
{
    Process();}

Foo(
    1,
    2);

// ✅ Preferred: closing token is on its own final line
if (isValid)
{
    Process();
}

Foo(
    1,
    2
);
```

Also, this pattern appears frequently in AI-generated code: LLMs often keep the closing `)` on the last argument line instead of moving it to a separate aligned line.

This rule enforces one consistent style, so multiline invocations and object creations remain easy to read.

## ⚙️ Configuration

You can configure severity and target syntax kinds via .editorconfig.
```.editorconfig
[*.cs]
dotnet_diagnostic.KUK0006.severity = warning # Incorrect multiline closing parenthesis placement | https://github.com/kurnakovv/kuker/wiki/KUK0006

dotnet_diagnostic.KUK0006.syntax_kinds = method_invocation,object_creation,method_declaration,constructor_declaration,primary_constructor # Optional | comma-separated syntax kinds; default is all supported kinds
```

## 💻 Examples
```cs
// ❌ KUK0006: closing parenthesis is on the same line as the last argument
var result1 = Foo(
    1,
    2);

// ❌ KUK0006: closing parenthesis is misaligned
var result2 = Foo(
    1,
    2
  );

// ✅ OK: closing parenthesis is on its own line and aligned
var result3 = Foo(
    1,
    2
);
```

Fluent call chain
```cs
// ❌ KUK0006
var result1 = Values()
    .Where(
        x => x > 0)
    .ToArray();

// ✅ OK
var result2 = Values()
    .Where(
        x => x > 0
    )
    .ToArray();
```

Object creation
```cs
// ❌ KUK0006
var dto1 = new MyDto(
    1,
    2);

// ✅ OK
var dto2 = new MyDto(
    1,
    2
);

// ✅ Also analyzed (implicit object creation)
MyDto dto3 = new(
    1,
    2
);
```

Method declaration
```cs
// ❌ KUK0006
public void Foo(
    int a,
    int b)
{
}

// ✅ OK
public void Foo(
    int a,
    int b
)
{
}
```

Local function
```cs
void M1()
{
    // ❌ KUK0006
    void Local(
        int a,
        int b)
    {
    }

    // ✅ OK
    void Local(
        int a,
        int b
    )
    {
    }
}
```

Interface / abstract method
```cs
// ❌ KUK0006
void Foo(
    int a,
    int b);

// ✅ OK
void Foo(
    int a,
    int b
);
```

Constructor declaration
```cs
// ❌ KUK0006
public MyClass(
    int a,
    int b)
{
}

// ✅ OK
public MyClass(
    int a,
    int b
)
{
}
```

Primary constructor
```cs
// ❌ KUK0006
public class MyClass(
    int a,
    int b)
{
    public int Sum { get; } = a + b;
}

// ✅ OK
public class MyClass(
    int a,
    int b
)
{
    public int Sum { get; } = a + b;
}
```



## 🗒️ Notes
* Scope | This rule analyzes syntax kinds supported by the current implementation and selected via `dotnet_diagnostic.KUK0006.syntax_kinds`. This includes method invocations (`InvocationExpression`), object creation expressions (`ObjectCreationExpression`, `ImplicitObjectCreationExpression`), method declarations (`MethodDeclaration`, `LocalFunctionStatement`), constructor declarations (`ConstructorDeclaration`), and primary constructors (`ClassDeclaration`, `StructDeclaration`, `RecordDeclaration`).

    ```cs
    // ✅ Analyzed (invocation)
    var result = Foo(
        1,
        2
    );

    // ✅ Analyzed (object creation)
    var dto = new MyDto(
        1,
        2
    );

    // ✅ Analyzed (method declaration)
    public void Foo(
        int a,
        int b
    )
    {
    }

    void M1()
    {
        // ✅ Analyzed (local function)
        void Local(
            int a,
            int b
        )
        {
        }
    }

    // ✅ Analyzed (primary constructor)
    public class MyClass(
        int a,
        int b
    )
    {
        public int Sum { get; } = a + b;
    }
    ```

* Single-line invocations | Calls where opening and closing parentheses are on the same line are ignored.

    ```cs
    // ✅ Ignored (single-line invocation)
    var sum = Add(1, 2);
    ```

* Trailing tokens | The rule checks placement/alignment of `)` but does not require it to be the only token on its line (for example, `); // comment` and `) + 1` are allowed).

    ```cs
    // ✅ Allowed: trailing comment after semicolon
    var result1 = Foo(
        1,
        2
    ); // comment

    // ✅ Allowed: additional expression after closing parenthesis
    var result2 = Foo(
        1,
        2
    ) + 1;
    ```

* Nested/compound endings | The analyzer allows closing patterns like `))`, `])`, `})` on one line when the nested closing token is already aligned correctly.

    ```cs
    // ✅ Allowed compound ending when alignment is correct
    var result = Values()
        .Select(x => new MyValue()
        {
            Original = x,
            Computed = Foo(
                x,
                x + 1
            ),
        })
        .ToArray();
    ```

* Code fix | A code fix is available and can automatically align or move the closing parenthesis in the IDE or via the [dotnet format](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-format) command.

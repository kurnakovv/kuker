## 💡 Title
Kuk0007ILoggerTypeMatchesContainingTypeAnalyzer

## 🆔 Rule ID
KUK0007

## 📝 Description
This rule detects `ILogger<T>` fields, properties, and constructor parameters where the type argument `T` does not match the class or struct that contains them.

The rule inspects **constructor parameters** first. If any constructor-level mismatch is found, field and property mismatches are not reported for that type (the fix for the constructor parameter is the primary action). Only when no constructor mismatches are present does the rule fall back to checking **fields and properties**.

## ⚙️ Configuration

You can configure the severity of the rule via `.editorconfig`.
```.editorconfig
[*.cs]
dotnet_diagnostic.KUK0007.severity = warning # ILogger<T> type argument does not match containing type | https://github.com/kurnakovv/kuker/wiki/KUK0007
```

## ❔ Why this is a problem
`ILogger<T>` uses `T` as the log category name. When the type argument does not match the containing type, log entries appear under the wrong category in structured logging systems (for example, Application Insights, Serilog, or OpenTelemetry). This makes it harder to filter, correlate, and understand logs.

This mistake often happens when a class is copied from another, or when the logger field is assigned from a constructor parameter that was accidentally typed with the wrong category.

## 💻 Example

```cs
// ❌ KUK0007: ILogger<T> type parameter 'PaymentService' does not match the containing type 'OrderService'
public class OrderService
{
    private readonly ILogger<PaymentService> _logger;

    public OrderService(ILogger<PaymentService> logger)
    {
        _logger = logger;
    }
}

// ✅ OK
public class OrderService
{
    private readonly ILogger<OrderService> _logger;

    public OrderService(ILogger<OrderService> logger)
    {
        _logger = logger;
    }
}
```

## 🗒️ Notes
* Scope | The rule analyzes `class`, `record`, `struct`, and `record struct` containing types. Interfaces, enums, and delegates are not checked.

* Priority | Constructor parameter mismatches take priority. When at least one constructor parameter has a mismatched `ILogger<T>`, field and property mismatches on the same type are suppressed. This avoids duplicate alerts in the same file for what is effectively the same root cause. Fix the constructor parameter first; the rule will then surface any remaining field/property issues (or use the available code fix - it will automatically update both the constructor parameter and all directly assigned members at once).

    ```cs
    // Both the constructor parameter and the field are mismatched, but only the
    // constructor parameter is reported (field is suppressed until it is fixed).
    public class OrderService
    {
        private readonly ILogger<PaymentService> _logger; // suppressed

        public OrderService(ILogger<PaymentService> logger) // ❌ reported
        {
            _logger = logger;
        }
    }
    ```

* Fields | A field mismatch is reported when there is no constructor mismatch on the same type.

    ```cs
    // ❌ KUK0007
    public class OrderService
    {
        private readonly ILogger<PaymentService> _logger;
    }

    // ✅ OK
    public class OrderService
    {
        private readonly ILogger<OrderService> _logger;
    }
    ```

* Properties | A read-only property mismatch is reported when there is no constructor mismatch on the same type.

    ```cs
    // ❌ KUK0007
    public class OrderService
    {
        public ILogger<PaymentService> Logger { get; }
    }

    // ✅ OK
    public class OrderService
    {
        public ILogger<OrderService> Logger { get; }
    }
    ```

* Generic classes | A generic class must use its own constructed type or its type parameter as the logger category. A bare type parameter (e.g. `ILogger<T>`) is also accepted because it still represents the actual runtime type of the containing class - the category will resolve correctly when the generic is instantiated.

    ```cs
    // ✅ OK: type argument matches the generic containing type
    public class GenericService<T>
    {
        private readonly ILogger<GenericService<T>> _logger;
    }

    // ✅ OK: bare type parameter is also accepted
    public class GenericService<T>
    {
        private readonly ILogger<T> _logger;
    }
    ```

* Properties with `set` or `init` | Properties are excluded when the setter is not private (for example: `public`, `internal`, `protected`, `protected internal`, or `init`). This avoids flagging properties that can be assigned from outside the type. Properties with `private set` or `private init` are still reported.

    ```cs
    // ✅ Not reported: publicly settable properties are excluded
    public ILogger<PaymentService> Logger { get; set; }
    public ILogger<PaymentService> Logger2 { get; init; }

    // ❌ KUK0007: private setter does not exclude the property
    public ILogger<PaymentService> Logger3 { get; private set; }
    ```

* Non-generic `ILogger`

    ```cs
    // ✅ Not analyzed
    private readonly ILogger _logger;
    ```

* Arrays | `ILogger<T>[]` is not analyzed. Collections of loggers typically represent more complex scenarios (for example, composite or decorator patterns) where abstract or interface types are intentional - enforcing a concrete type match would produce false positives in those cases.

    ```cs
    // ✅ Not analyzed
    private readonly ILogger<PaymentService>[] _loggers;
    ```

* Nested classes | Each type is analyzed independently. A nested class must use its own type as the logger category, not the outer class type.

    ```cs
    public class OrderService
    {
        public class Inner
        {
            // ❌ KUK0007: category should be 'Inner', not 'OrderService'
            private readonly ILogger<OrderService> _logger;

            // ✅ OK
            private readonly ILogger<Inner> _logger2;
        }
    }
    ```

* Code fix | A code fix is available. It offers two actions depending on context:
    - **"Change ILogger\<T\> to ILogger\<ContainingType\> for constructor and assigned members"** - updates the constructor parameter type and rewrites all `this.member = parameter` assignments in the constructor body that directly receive the logger parameter.
    - **"Change ILogger\<T\> to ILogger\<ContainingType\>"** - updates only the field or property type when there is no constructor mismatch.

    The fix is also available via the [dotnet format](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-format) command.

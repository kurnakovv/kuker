## 💡 Title
Kuk0009DeclarationHeaderSeparationAnalyzer

## 🆔 Rule ID
KUK0009

## 📝 Description
This rule enforces a blank line before a declaration (class, method, property, field, enum member, etc.) when that declaration has a "header" above it - attributes, comments, or XML documentation comments. If the header is not separated from the previous declaration by a blank line, a diagnostic is reported.

## ⚙️ Configuration

You can configure the severity of the rule via `.editorconfig`.
```.editorconfig
[*.cs]
dotnet_diagnostic.KUK0009.severity = warning # Missing blank line before declaration header | https://github.com/kurnakovv/kuker/wiki/KUK0009
```

## ❔ Why this is a problem
When a header (attributes, comments, or XML docs) immediately follows the previous member with no blank line, it visually blends with the previous declaration, making it harder to tell where one member ends and the next one begins. A consistent blank line before each header improves readability and keeps the structure of the file easy to scan.

## 💻 Example

❌ KUK0009: no blank line before the XML documentation header
```cs
class User
{
    /// <summary>
    /// User name.
    /// </summary>
    public string Name { get; set; }
    /// <summary>
    /// User age.
    /// </summary>
    public int Age { get; set; }
}
```

✅ OK: blank line before the XML documentation header
```cs
class User
{
    /// <summary>
    /// User name.
    /// </summary>
    public string Name { get; set; }

    /// <summary>
    /// User age.
    /// </summary>
    public int Age { get; set; }
}
```

## 🗂️ Notes
* Attributes on the same line | If the attribute list is on the same line as the declaration itself, it is still treated as part of the header and must be separated from the previous member by a blank line.

    ```cs
    // ✅ OK
    public string Name { get; set; }

    [Obsolete]
    public int Age { get; set; }
    ```

* No header | Declarations with no attributes, comments, or XML documentation comments above them are not affected by this rule.
